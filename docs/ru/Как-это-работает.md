# Как это работает

← [На главную](Home.md)

splify смотрит, **куда** идёт трафик, и решает, **как** его отправить:

```
                       ┌────────────────────────┐
  Устройства  ──────▶  │        splify          │
   в вашей            │  заблокировано? ──▶ VPN  │ ──▶ 🔒 туннель ──▶ интернет
   сети               │  обычный сайт?  ──▶ напрямую │ ──▶ 🌐 ваш провайдер
                       └────────────────────────┘
```

- **Заблокированные и зарубежные сайты** идут через VPN-туннель — их не видно
  провайдеру, и блокировки обходятся.
- **Всё остальное** (российские сайты, банки, видео) идёт **напрямую** — на полной
  скорости, без лишнего крюка через VPN.

Список «что блокировать» splify скачивает автоматически и обновляет раз в сутки, так что вам не нужно ничего вести вручную.

### Маршрутизация по SNI («Ход конём»)
Если в вашей системе установлен пакет `zapret` (`nfqws`), easyunblock умеет маршрутизировать трафик не по IP-адресам, а по доменам из TLS ClientHello (SNI):
1. **Анализ только первого пакета**: Перехватывается только первый пакет сессии в NFQUEUE. `nfqws` считывает домен (SNI) за микросекунду и ставит метку на соединение (`connmark 0x1` для заблокированных, `connmark 0x2` для обычных).
2. **Прокачка через ядро на скорости провода**: Все последующие гигабайты трафика этой сессии летят напрямую через ядро Linux (минуя NFQUEUE и процессор). Нагрузка на CPU — 0%, потребление памяти — всего ~2 МБ.
3. **Решение проблемы Cloudflare**: Если на одном IP-адресе Cloudflare висит и заблокированный сайт, и обычный — каждый из них пойдёт своим маршрутом по отдельной TCP-сессии.
4. **Решение проблемы QUIC**: UDP 443 (HTTP/3) блокируется для LAN, чтобы браузер за 50 мс мгновенно переходил на TCP 443, где его подхватывает анализ SNI.

Если туннель вдруг отвалится, splify сам переключится на запасной (если он настроен) или временно включит обход блокировок на прямом канале — чтобы вы не остались без интернета.
